## 2. Pre-Migration Inventory

### 2.1 Couchbase Document Types to PostgreSQL Tables

| Couchbase `type`          | Couchbase Collection                        | PostgreSQL Table               | Strategy                                              |
| ------------------------- | ------------------------------------------- | ------------------------------ | ----------------------------------------------------- |
| `user`                    | `users`                                     | `users`                        | UUID primary key; `profile` kept as JSONB             |
| `availability`            | `users` (filtered by `type='availability'`) | `trainer_availabilities`       | UUID PK; `start_time`/`end_time` parsed to `TIME`     |
| `body_measurement`        | `body_measurements`                         | `body_measurements`            | UUID PK; `parts` JSONB (source of truth) + GIN idx    |
| `coaching_request`        | `coaching_requests`                         | `coaching_requests`            | UUID primary key                                      |
| `comment`                 | `comments`                                  | `comments`                     | UUID PK; `target_id` polymorphic UUID (no FK)         |
| `exercise`                | `exercises`                                 | `exercises`                    | UUID PK + `legacy_id TEXT UNIQUE` for seeded non-UUID |
| `invitation`              | `invitations`                               | `invitations`                  | UUID primary key                                      |
| `meal`                    | `meals`                                     | `meals`                        | UUID PK; `items` JSONB array                          |
| `relationship`            | `relationships`                             | `relationships`                | UUID primary key                                      |
| `review`                  | `reviews`                                   | `trainer_reviews`              | UUID primary key                                      |
| `workout`                 | `workouts`                                  | `workouts`                     | UUID PK; `exercises` JSONB array                      |
| `workout_plan`            | `workout_plans`                             | `workout_plans`                | UUID PK; `exercises` JSONB array (with `order`)       |
| `workout_plan_assignment` | `workout_plan_assignments`                  | `workout_plan_assignments`     | UUID primary key                                      |

> **Note on `availability` source:** In the current Couchbase codebase, availability slots are stored in the **`users`** collection (not a dedicated collection), keyed by `type='availability'`. See `backend/internal/domain/repositories/availability_repository.go`. The migration export must filter the `users` collection by `type` rather than reading a separate collection. Verify all other collection names against `backend/internal/config/collections.go` before exporting.

### 2.2 ID Mapping

- Couchbase uses string document IDs (e.g., `user::123`, `workout::abc`). Every domain document already carries its own UUID string field (`workoutId`, `planId`, `measurementId`, etc.) generated by `uuid.New().String()` in the model constructors (see `models.NewWorkout`, `models.NewBodyMeasurement`, `models.NewWorkoutPlan`, etc.).
- Cross-references between documents are **also UUID strings**: `Workout.PlanID` -> `WorkoutPlan.PlanID`, `WorkoutExercise.ExerciseID` -> `Exercise.ExerciseID`, `Comment.ParentCommentID` -> `Comment.CommentID`, `WorkoutPlanAssignment.PlanID` -> `WorkoutPlan.PlanID`.
- **Decision: All PostgreSQL domain tables use `UUID` primary keys** (default `gen_random_uuid()`). Rationale:
  1. Eliminates the FK type mismatch - every `*_id` column is `UUID`, so all FKs compile.
  2. Preserves all existing cross-references verbatim - no `legacy_id` rewrite for most tables, no ID rewriting inside JSONB arrays (except `exercises`, see below).
  3. No frontend type churn - `frontend/src/types/index.ts` already types every ID as `string`.
  4. Matches the existing Couchbase data model 1:1.
- **Rule for all domain tables:** use the document's own UUID field (e.g., `workoutId`, `planId`) as the PK - not the Couchbase document key. Strip the type prefix from the key only if you fall back to it; otherwise prefer the field.
- **Exception - lookup tables (`muscle_groups`, `equipment_definitions`):** keep `SERIAL`/`INTEGER` PKs. These are stable enumerations seeded by `config/seed_data.go` with small integer IDs (1-8), and `models.Exercise.MuscleGroupID` / `EquipmentID` are typed `int`. Their FKs in `exercises` remain `INTEGER`.
- **Exception - `exercises.legacy_id`:** seeded exercises use non-UUID IDs like `"exercise_Bench Press"` (see `config/seed_data.go:196`). The `exercises` table adds a `legacy_id TEXT UNIQUE` column; migration generates a deterministic UUID (v5 from a fixed namespace + legacy ID) for non-UUID exercise IDs and rewrites every `exerciseId` reference inside `workouts.exercises` and `workout_plans.exercises` JSONB arrays using the legacy->UUID map. Custom exercises (created via API) already have UUID `exerciseId` values and need no rewrite.

## 3. Target Schema (PostgreSQL)

> **Convention:** Every domain table uses `UUID` primary keys (default `gen_random_uuid()`), matching the UUID strings already used as document IDs and cross-reference fields in Couchbase. Lookup tables (`muscle_groups`, `equipment_definitions`) keep `SERIAL`/`INTEGER` PKs because `models.Exercise.MuscleGroupID` / `EquipmentID` are typed `int` and reference stable seeded enumerations.

### 3.3 Body Measurements (JSONB `parts` + Expression Indexes)

> `models.BodyMeasurement.Parts` is a `map[string]BodyMeasurementPart` supporting custom parts beyond `SupportedBodyParts`. Hardcoding 13 columns would silently drop custom data. Instead, `parts` is JSONB source of truth; expression indexes on the 13 supported paths provide fast chart queries.

```sql
CREATE TABLE body_measurements (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    athlete_id UUID NOT NULL REFERENCES users(user_id) ON DELETE CASCADE,
    date DATE NOT NULL,
    weight DECIMAL(10,2) NOT NULL CHECK (weight >= 0),
    weight_unit VARCHAR(3) NOT NULL CHECK (weight_unit IN ('kg','lbs')),
    body_fat_pct DECIMAL(5,2) CHECK (body_fat_pct >= 0 AND body_fat_pct <= 100),
    parts JSONB NOT NULL DEFAULT '{}',
    notes TEXT CHECK (LENGTH(notes) <= 500),
    created_at TIMESTAMPTZ DEFAULT NOW(),
    updated_at TIMESTAMPTZ DEFAULT NOW()
);
CREATE INDEX idx_bm_athlete_date ON body_measurements(athlete_id, date);
CREATE INDEX idx_bm_athlete_weight ON body_measurements(athlete_id, weight);
CREATE INDEX idx_bm_chest   ON body_measurements(athlete_id, ((parts->>'chest')::numeric))   WHERE parts ? 'chest';
CREATE INDEX idx_bm_waist   ON body_measurements(athlete_id, ((parts->>'waist')::numeric))   WHERE parts ? 'waist';
CREATE INDEX idx_bm_hips    ON body_measurements(athlete_id, ((parts->>'hips')::numeric))    WHERE parts ? 'hips';
CREATE INDEX idx_bm_bicep_left  ON body_measurements(athlete_id, ((parts->>'bicepLeft')::numeric))  WHERE parts ? 'bicepLeft';
CREATE INDEX idx_bm_bicep_right ON body_measurements(athlete_id, ((parts->>'bicepRight')::numeric)) WHERE parts ? 'bicepRight';
-- Additional expression indexes for remaining SupportedBodyParts follow the same pattern
CREATE INDEX idx_bm_parts_gin ON body_measurements USING GIN (parts);
```

## 4. Data Migration Pipeline

Since no production users exist, use an offline migration.

```
Couchbase (Export JSONL) -> Transform (Go) -> PostgreSQL (COPY)
```

### 4.1 Load Order (FK dependencies)

1. `users` (no FKs)
2. `muscle_groups`, `equipment_definitions` (re-seed from `config/seed_data.go` with existing integer IDs 1-8)
3. `exercises` (FK -> users, muscle_groups, equipment_definitions). If `exerciseId` is not a UUID (seeded exercises like `"exercise_Bench Press"`), generate a deterministic UUID v5, store legacy_id, build `legacyIDMap`.
4. `relationships`, `coaching_requests`, `trainer_reviews`, `invitations`, `trainer_availabilities`
5. `workout_plans` - rewrite `exerciseId` inside `exercises` JSONB using `legacyIDMap`
6. `workouts` - rewrite `exerciseId` inside `exercises` JSONB using `legacyIDMap`
7. `meals`
8. `body_measurements` - `parts` JSONB copies verbatim
9. `workout_plan_assignments`
10. `comments` - `target_id` is polymorphic UUID, no FK validation

### 4.2 Source Collection Mapping

- `availability` documents live in the **`users`** collection filtered by `type='availability'`. See `availability_repository.go`.
- Verify all other collection names against `backend/internal/config/collections.go`.

### 4.3 Transform Rules

- `start_time`/`end_time` strings ("HH:MM") -> `TIME`
- `workout_plan_assignment.status` = always `'active'`
- `exercises.exerciseId` rewrite per §4.1 steps 3, 5, 6
- `body_measurements.parts` copies through verbatim
- `users.profile` copies verbatim. `profile.clientList` and `profile.trainerAssignment` are denormalized caches - stop writing them post-migration and compute from `relationships` at read time

## 5. Application Code Changes

### 5.1 DI Wiring Strategy: Keep Interfaces, Swap Implementations

**Strategy:** All 14 repository interfaces in `internal/domain/repositories/` stay **unchanged**. Only the concrete implementations swap from `Couchbase*Repository` to `Postgres*Repository`. Services depend on the interfaces, so service code is untouched.

**Driver stack (add to `go.mod`):**
- `github.com/jackc/pgx/v5` + `github.com/jackc/pgx/v5/pgxpool` - connection pool
- `github.com/jmoiron/sqlx` - ergonomic `GetContext`/`SelectContext`, layered on pgx via `pgx/v5/stdlib`

**File layout:**
- New: `internal/repository/postgres/` - one file per repo (`workout.go`, `meal.go`, etc.)
- Existing: `internal/domain/repositories/*.go` - keep interfaces + Couchbase impls during transition (rollback = one-line fx swap)

**`internal/app/module.go` changes:**

1. Replace Couchbase connection provider with pgxpool:

```go
// Before
fx.Provide(func(cfg *config.Config) (*gocb.Cluster, *gocb.Bucket, error) {
    return config.ProvideCouchbaseConnection(cfg)
})

// After
fx.Provide(func(cfg *config.Config) (*pgxpool.Pool, error) {
    return config.ProvidePostgresPool(cfg)
})
```

2. Replace each repository constructor (interface return type unchanged):

```go
// Before
func(cluster *gocb.Cluster, bucket *gocb.Bucket) repositories.WorkoutRepository {
    return repositories.NewWorkoutRepository(cluster, bucket)
}

// After
func(pool *pgxpool.Pool) repositories.WorkoutRepository {
    return postgres.NewWorkoutRepository(pool)
}
```

3. Remove `*gocb.Cluster`/`*gocb.Bucket` from `AppProvider` and `config.GlobalCluster`/`config.GlobalBucket`.
4. `config.InitializeCollections()` no longer needed - schema managed via `golang-migrate`.

**Repository example - Before (Couchbase):**

```go
type CouchbaseWorkoutRepository struct {
    cluster *gocb.Cluster
    bucket  *gocb.Bucket
}

func (r *CouchbaseWorkoutRepository) GetByID(ctx context.Context, workoutID string) (*models.Workout, error) {
    result, err := r.bucket.Scope(config.ScopeDefault).Collection(config.CollectionWorkouts).Get(workoutID, &gocb.GetOptions{Context: ctx})
    if err != nil { /* ... */ }
    var workout models.Workout
    if err := result.Content(&workout); err != nil { /* ... */ }
    return &workout, nil

```

**After (PostgreSQL) - same interface, new impl:**

```go
type PostgresWorkoutRepository struct {
    db *sqlx.DB // wrapped pgxpool via pgx/v5/stdlib
}

func NewWorkoutRepository(pool *pgxpool.Pool) *PostgresWorkoutRepository {
    return &PostgresWorkoutRepository{db: sqlx.NewDb(stdlib.OpenDBFromPool(pool), "pgx")}
}

func (r *PostgresWorkoutRepository) GetByID(ctx context.Context, workoutID string) (*models.Workout, error) {
    var row struct {
        ID        string    `db:"id"`
        AthleteID string    `db:"athlete_id"`
        Date      time.Time `db:"date"`
        PlanID    *string   `db:"plan_id"`
        Exercises []byte    `db:"exercises"`
        CreatedAt time.Time `db:"created_at"`
        UpdatedAt time.Time `db:"updated_at"`
    }
    if err := r.db.GetContext(ctx, &row, `
        SELECT id, athlete_id, date, plan_id, exercises, created_at, updated_at
        FROM workouts WHERE id = $1
    `, workoutID); err != nil {
        if errors.Is(err, sql.ErrNoRows) {
            return nil, domainerrors.ErrNotFound
        }
        return nil, fmt.Errorf("failed to get workout: %w", err)
    }
    workout := &models.Workout{
        Type: "workout", WorkoutID: row.ID, AthleteID: row.AthleteID,
        Date: row.Date, CreatedAt: row.CreatedAt, UpdatedAt: row.UpdatedAt,
    }
    if row.PlanID != nil { workout.PlanID = *row.PlanID }
    if err := json.Unmarshal(row.Exercises, &workout.Exercises); err != nil {
        return nil, fmt.Errorf("failed to decode exercises JSONB: %w", err)
    }
    return workout, nil
}
```

> **Notes:** `GetByID` keeps its `string` parameter - UUIDs flow as strings throughout (matching existing interface and frontend contract). Preserve the `utils.Clock` pattern for `updated_at`. `CoachingRequest` uses `cbjson` tags - fix to `json` or handle in migration exporter.

### 5.2 Repository Example: Body Measurements (JSONB `parts`)

With `parts` stored as JSONB, no per-column NULL handling - custom parts round-trip automatically.

```go
type PostgresBodyMeasurementRepository struct {
    db *sqlx.DB
}

func (r *PostgresBodyMeasurementRepository) GetByAthleteID(ctx context.Context, athleteID string, limit, offset int) ([]*models.BodyMeasurement, error) {
    var rows []struct {
        ID         string    `db:"id"`
        AthleteID  string    `db:"athlete_id"`
        Date       time.Time `db:"date"`
        Weight     float64   `db:"weight"`
        WeightUnit string    `db:"weight_unit"`
        BodyFatPct float64   `db:"body_fat_pct"`
        Parts      []byte    `db:"parts"`
        Notes      string    `db:"notes"`
        CreatedAt  time.Time `db:"created_at"`
        UpdatedAt  time.Time `db:"updated_at"`
    }
    if err := r.db.SelectContext(ctx, &rows, `
        SELECT id, athlete_id, date, weight, weight_unit, body_fat_pct, parts, notes, created_at, updated_at
        FROM body_measurements WHERE athlete_id = $1
        ORDER BY date DESC LIMIT $2 OFFSET $3
    `, athleteID, limit, offset); err != nil {
        return nil, fmt.Errorf("failed to query body measurements: %w", err)
    }
    measurements := make([]*models.BodyMeasurement, 0, len(rows))
    for _, row := range rows {
        m := &models.BodyMeasurement{
            Type: "body_measurement", MeasurementID: row.ID,
            AthleteID: row.AthleteID, Date: row.Date,
            Weight: row.Weight, WeightUnit: models.WeightUnit(row.WeightUnit),
            BodyFatPct: row.BodyFatPct, Notes: row.Notes,
            CreatedAt: row.CreatedAt, UpdatedAt: row.UpdatedAt,
            Parts: make(map[string]models.BodyMeasurementPart),
        }
        if len(row.Parts) > 0 {
            if err := json.Unmarshal(row.Parts, &m.Parts); err != nil {
                return nil, fmt.Errorf("failed to decode parts JSONB: %w", err)
            }
        }
        measurements = append(measurements, m)
    }
    return measurements, nil
}
```

### 5.3 Query Pattern Mapping

| Couchbase Pattern                                 | PostgreSQL Equivalent                                                      |
| ------------------------------------------------- | -------------------------------------------------------------------------- |
| `SELECT * WHERE type='workout' AND athleteId='x'` | `SELECT * FROM workouts WHERE athlete_id = $1` (no `type` col)             |
| `ANY i IN items SATISFIES i.food = 'chicken'`     | `SELECT * FROM meals WHERE items @> $1` (param is JSONB, see §5.4)         |
| `ORDER BY date DESC LIMIT 1`                      | `ORDER BY date DESC LIMIT 1`                                               |
| N1QL aggregation                                  | Standard SQL `GROUP BY` + window functions                                 |
| `MutateIn` on `isBooked`                          | `UPDATE trainer_availabilities SET is_booked = TRUE, updated_at = NOW()`   |
| `MutateIn` append to `exercises` JSONB            | `UPDATE workouts SET exercises = exercises || $1::jsonb WHERE id = $2`     |

### 5.4 JSONB Query Helpers (Go) - Parameterized, SQL-injection-safe

```go
// Workouts containing a specific exercise ID (exercises @> $1)
func WorkoutHasExerciseFilter(exerciseID string) []byte {
    b, _ := json.Marshal([]map[string]string{{"exerciseId": exerciseID}})
    return b
}

// Meals containing a specific food (items @> $1)
func MealContainsFoodFilter(food string) []byte {
    b, _ := json.Marshal([]map[string]string{{"food": strings.ToLower(food)}})
    return b
}
```

```sql
SELECT date,
       (parts->>'chest')::numeric AS chest,
       (parts->>'waist')::numeric AS waist,
       (parts->>'hips')::numeric  AS hips
FROM body_measurements WHERE athlete_id = $1 AND date >= $2 AND date <= $3 ORDER BY date;

-- Custom part (not in SupportedBodyParts) - covered by GIN index
SELECT date, (parts->>'leftWrist')::numeric AS left_wrist
FROM body_measurements WHERE athlete_id = $1 AND parts ? 'leftWrist' ORDER BY date;
```

### 6.2 Workout Volume Progression (per exercise)

Sums volume across **all** sets (not just set[0]) using lateral joins:

```sql
SELECT w.date,
       e.value->>'name' AS exercise_name,
       SUM((s.value->>'weight')::numeric * (s.value->>'reps')::int) AS volume
FROM workouts w,
     jsonb_array_elements(w.exercises) AS e(value),
     jsonb_array_elements(e.value->'sets') AS s(value)
WHERE w.athlete_id = $1
  AND e.value->>'exerciseId' = $2
  AND (s.value->>'completed')::boolean = true
  AND w.date >= $3
GROUP BY w.date, e.value->>'name'
ORDER BY w.date;
```

### 6.3 Macro Intake Over Time

```sql
SELECT date,
       SUM((i.value->>'calories')::numeric) AS calories,
       SUM((i.value->'macros'->>'protein')::numeric) AS protein,
       SUM((i.value->'macros'->>'carbs')::numeric) AS carbs,
       SUM((i.value->'macros'->>'fats')::numeric) AS fats
FROM meals m, jsonb_array_elements(m.items) i
WHERE m.athlete_id = $1 AND m.date >= $2
GROUP BY m.date ORDER BY m.date;
```

### 6.4 Personal Record (PR) Detection

Finds max weight across **all** completed sets (fixes `{0,completed'` typo and set[0] limitation from v1.0):

```sql
WITH ranked_sets AS (
    SELECT w.date,
           (s.value->>'weight')::numeric AS weight,
           (s.value->>'reps')::int AS reps,
           ROW_NUMBER() OVER (
               PARTITION BY e.value->>'exerciseId'
               ORDER BY (s.value->>'weight')::numeric DESC NULLS LAST, (s.value->>'reps')::int DESC
           ) AS rn
    FROM workouts w,
         jsonb_array_elements(w.exercises) AS e(value),
         jsonb_array_elements(e.value->'sets') AS s(value)
    WHERE w.athlete_id = $1
      AND e.value->>'exerciseId' = $2
      AND (s.value->>'completed')::boolean = true
)
SELECT date, weight, reps FROM ranked_sets WHERE rn = 1;
```

### JSONB Indexing Cheat Sheet

```sql
-- GIN for containment queries (@>, ?) on arrays
CREATE INDEX idx_workouts_exercises_gin ON workouts USING GIN (exercises);
CREATE INDEX idx_meals_items_gin      ON meals    USING GIN (items);
CREATE INDEX idx_plan_exercises_gin   ON workout_plans USING GIN (exercises);

-- GIN for arbitrary keys in body measurement parts
CREATE INDEX idx_bm_parts_gin ON body_measurements USING GIN (parts);

-- Expression index for specific JSONB path (example: exercise name)
CREATE INDEX idx_workouts_exercise_name ON workouts ((exercises ->> 'name'));
```

### ID Type Handling in Application

- **All domain tables**: UUID PKs - serialize as strings in JSON (Go's `encoding/json` handles this natively).
- **Lookup tables**: INTEGER PKs, referenced by `int` fields in `models.Exercise`.
- **No middleware needed** - every domain ID is a UUID string; `frontend/src/types/index.ts` types every ID as `string` already.

### Body Measurement `parts` Handling

- `parts` is JSONB source of truth, mirroring `models.BodyMeasurement.Parts` (`map[string]BodyMeasurementPart`).
- On read: `json.Unmarshal(row.Parts, &m.Parts)` - custom parts round-trip automatically.
- On write: `json.Marshal(measurement.Parts)` -> bind to `parts` column.
- 13 supported parts have expression indexes (§3.3); custom parts use the GIN index.

### Migration Notes

- **All domain tables use UUID PKs** to match Couchbase document IDs and cross-references verbatim.
- **Lookup tables use SERIAL** because `Exercise.MuscleGroupID`/`EquipmentID` are typed `int`.
- **`exercises`** has a `legacy_id` column for non-UUID seeded IDs; migration rewrites `exerciseId` refs in JSONB arrays.
- Workout exercises and meal items remain as JSONB arrays (preserves per-set UUIDs, per-item macros).
- Body measurements use JSONB `parts` (preserves custom parts; expression indexes for common chart queries).
- The `type = '...'` Couchbase predicate disappears - PostgreSQL tables are typed.
